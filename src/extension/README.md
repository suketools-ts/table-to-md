# 表エディタ for Backlog（Chrome / Edge 拡張機能）

Backlog の課題編集画面で、表を表計算のように編集するための拡張機能です。
Manifest V3 で作っているので、同じパッケージが Chrome と Edge の両方で動きます。

> この拡張機能は個人が開発したものであり、株式会社ヌーラボおよび Backlog の
> 公式製品ではありません。名前を「〜 for Backlog」としているのは、公式製品と
> 誤解されないようにするためです（ストアの審査基準への対応）。

変換ロジックは Web アプリ版と同じ `src/lib` をそのまま使っています。

## できること

### ① 入力欄で右クリック →「カーソル位置の表を編集 / 新規作成」

入力欄（`<textarea>` または contenteditable）の上でだけメニューが出ます。

- カーソルが表の上にあれば、その表を読み込んでグリッドで編集し、元の範囲を置き換えます。
- 表の上に無ければ、空の表を作ってカーソル位置に挿入します。前後の地の文とくっついて
  誤解釈されないよう、空行で挟みます。

**記法は自動判定します。** 見出し行の `|h`、セル頭の `~`、セル内改行の `&br;` があれば
Backlog 記法、区切り行（`| --- |`）があれば Markdown と判断します。新規作成のときは
表そのものが無いので、入力欄全体の書きぶりから推定します。**どちらとも判断できない
ときは Backlog 記法**を選びます。判定結果は画面下部に表示され、必要なら手動で
変えられます。

### ② 表示中の表で右クリック →「この表を Markdown / Backlog 記法に変換」

既存のコメントや課題の説明に書かれた表を、ソースに起こし直すための機能です。
**範囲選択は要りません。** 表のセルの上で右クリックすればその表が対象になります。

変換結果はダイアログに表示され、**記法をその場で切り替えながら**中身を確かめて
コピーできます（表示中の表からソースを起こすとき、どちらの記法で欲しいかは
その場の用途によって変わるため、選べるようにしています）。タブは
**Backlog 記法 → Markdown** の順で、既定は Backlog 記法です。

- 表の外（同じコメント内の段落など）で右クリックしても、近くの表を探します。
  ただしさかのぼる範囲には上限があり、離れた位置の無関係な表は拾いません。
- 範囲選択しているときはそちらが優先されます。表の一部だけをドラッグしていても
  表全体を対象にします（半端な行だけ取り出しても使い道が無いため）。
- `colspan` / `rowspan` は結合元の値を複製して展開します。

## ビルドと読み込み

```sh
npm run build:extension   # dist-extension/ に出力
```

1. Chrome / Edge で `chrome://extensions`（Edge は `edge://extensions`）を開く
2. 「デベロッパーモード」を有効にする
3. 「パッケージ化されていない拡張機能を読み込む」で `dist-extension/` を選ぶ

コードを変えたら `npm run build:extension` をやり直し、拡張機能一覧の再読み込みボタンを押します。

## ストアへの公開

Chrome ウェブストアと Microsoft Edge アドオンに出すための文面・チェックリスト・
スクリーンショットを [`store/`](../../store/) にまとめてあります。zip の作り方、
単一用途の説明、権限ごとの使用理由、データ利用の申告など、そのまま貼れる形です。

プライバシーポリシーの本文は [`docs/privacy.md`](../../docs/privacy.md) です。

## 対象ドメイン

`*.backlog.com` / `*.backlog.jp` / `*.backlogtool.com` を対象にしています。
別のドメインで使う場合は `src/extension/manifest.json` の `host_permissions` と
`content_scripts.matches` に足してください。

## 動作確認

表の変換ロジックは vitest（`npm test`）で押さえていますが、**入力欄への書き戻しだけは
ブラウザとエディタの実装に強く依存する**ので、実ブラウザで通しの確認をします。

```sh
npx playwright install chromium   # 初回のみ。ブラウザ本体を取得する
npm run test:extension
```

確認する内容は次のとおりです。すべて期待どおりなら `すべて期待どおりです。` と出て
終了コード 0、違いがあれば期待値と実際の値を並べて終了コード 1 になります。

| 確認する場面 | 内容 |
| --- | --- |
| ProseMirror の表を編集 | 記法を自動判定する / 段落ごとに 1 行として読む / 元の表だけを置き換える |
| ProseMirror に新規挿入 | 新規作成として開く / 前後を空行で挟む |
| 空のコメント欄に挿入 | テキストノードが無い状態でも挿入できる（ProseMirror / 素の contenteditable） |
| ProseMirror で記法を切替 | Markdown に変換し桁そろえを保つ |
| textarea の表を編集 | 表の範囲だけを置き換える |
| 記法の既定 | 目印の無い表・空の入力欄では Backlog 記法を選ぶ |
| フォーカスの行き来 | 開くとダイアログへ移る / クリックせず入力できる / 打鍵が後ろへ漏れない / セル編集中の Esc では閉じない / 閉じると入力欄へ戻る |
| 表示中の表を変換 | ダイアログが開く / タブの並び / 既定で Backlog 記法 / Markdown へ切替 / コピー / 表の外で右クリックしても拾う / rowspan の展開 / 表が無ければそう伝える |

ブラウザの場所を自分で指定したい場合は `PLAYWRIGHT_CHROMIUM_PATH` を使えます。

**これは検証用ページに対する確認で、実際の Backlog に対するものではありません。**
Backlog 自身のスキーマや貼り付けフックまでは再現できないため、実機での確認は
別途必要です。

`extension-test/` に 2 つの検証用ページがあります。

| ページ | 内容 |
| --- | --- |
| `prosemirror.html` | **本物の ProseMirror** で Backlog のコメント欄と同じ構成を再現したもの |
| `fixture.html` | `<textarea>`・素の contenteditable・表示用テーブルを並べたもの |

どちらも `chrome` API を最小限だけ模倣しているので、拡張機能を読み込まなくても
コンソールから `__send({ type: 'edit-table' })` で手動でも試せます
（ES モジュールを使うため `file://` ではなく HTTP で開いてください）。

## 実装上の要点

**右クリックした要素の特定** — メニューのクリックはサービスワーカー側に届きますが、
どの要素を右クリックしたかは分かりません。コンテンツスクリプト側で `contextmenu` を
capture 段階で拾い、対象の要素とカーソル位置を控えています。

**入力欄の読み取り** — Backlog のコメント欄は ProseMirror で、1 行が 1 つの `<p>` です。
`innerText` はブロック要素に余分な改行を入れるため行がずれる（実測で
`テスト文書\n\n\n\n\n|header1...` のようになる）ので、ブロック要素を 1 行として
自前で組み立てています。あわせて、文字位置から DOM の位置を引ける対応表も作ります。

**右クリック対象の特定** — 右クリックの対象は編集ホストではなく中の `<p>` になります。
contenteditable は子孫に継承されるので `<p>` 自体も `isContentEditable` が true になり、
そのまま扱うと段落 1 つだけを入力欄と誤認します。編集可能な祖先をたどって根本を取ります。

**textarea への書き戻し** — `document.execCommand('insertText')` を第一手にしています。
古い API ですが、ページ側の取り消し履歴（Ctrl+Z）を保ったまま挿入でき、`input` イベントも
発生する手段です。使えない場合は、`value` のプロトタイプ setter を通してから
`input` を発火させる経路に落ちます（React などが値を監視している場合に変更を拾わせるため）。

**空の入力欄への挿入** — 書き戻しの位置は「文字位置 → テキストノード」の対応表から
求めていますが、まだ何も書かれていない入力欄にはテキストノードがありません。Backlog の
コメント欄が空のときは `<p><br class="ProseMirror-trailingBreak"></p>` が 1 つあるだけです。
この場合は位置を計算しようがないので、入力欄の中身全体を選択範囲にして貼り付けます。

**リッチエディタへの書き戻し** — ProseMirror は DOM を直接書き換えられることを想定して
おらず、自前で入力を解釈して内部状態を更新します。ここには 3 つの落とし穴があり、
いずれも実際に動かして分かったものです。

1. **エディタは自前の選択状態を持つ。** DOM の選択を変えただけでは伝わらず、
   貼り付けが元のカーソル位置に入って古い表が消えませんでした。フォーカスを戻し、
   選択を上書きし、`selectionchange` が伝わるのを待ってから貼り付けます。
2. **プレーンテキストの貼り付けでは空行を作れない。** ProseMirror は
   `split(/(?:\r\n?|\n)+/)` で行に割るため連続する改行が 1 つに潰れます。
   Markdown の表は直前に空行が無いと表として解釈されないので、`<p>` を並べた
   `text/html` も一緒に渡します。
3. **HTML は連続する空白を畳む。** そのままだと桁そろえの空白が失われるので、
   各段落に `white-space: pre-wrap` を指定します。これで空行と桁そろえの両方が残ります。

**フォーカスの受け渡し** — 右クリックメニューから開くので、そのままではフォーカスが
ページの入力欄に残り、打鍵が後ろの入力欄へ流れてしまいます。開いたらグリッドの
入力受け（隠しテキストエリア）へフォーカスを移し、閉じたら元の要素へ戻します。
React の描画は非同期なので、移す先が出来てからでないと掴めません。ここだけ
`flushSync` で同期的に描画しています。

書き戻しは選択範囲を組み立てながら進むため、途中でフォーカスが動くと挿入位置が
ずれます。そのため「この内容で置き換える」では、先に閉じてフォーカスを入力欄へ
戻してから書き戻します。

Esc で閉じる判定もこれに合わせて変えています。グリッドにフォーカスがあるかどうかでは
セル編集中かを判別できない（編集していなくても隠しテキストエリアが掴んでいる）ので、
セルの入力欄が開いているか（`masume-grid-editor--hidden` が外れているか）で見ます。

**画面の隔離** — 編集画面は Shadow DOM の中に立てています。ページ側の CSS を持ち込まず、
こちらの CSS も外へ漏らしません。スタイルは `?inline` で文字列として取り込み、
シャドウルート内に閉じ込めています。

**クリップボード** — 右クリックメニュー経由だとユーザー操作の引き継ぎが切れて
`navigator.clipboard` が拒否されることがあります。共有している `src/lib/clipboard.ts` が
`execCommand('copy')` に落ちる作りなので、そのまま効きます。
